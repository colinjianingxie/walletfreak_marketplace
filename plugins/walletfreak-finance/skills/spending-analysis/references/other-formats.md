# Other banks, Excel and PDF statements

The local importer accepts UTF-8 comma-separated CSVs with a header row. Use the preview's column mappings for other banks. Canonical headers: Date, Description, Amount, Currency, Category, Type. Dates use YYYY-MM-DD; purchases/fees/interest are positive outflows, refunds/income negative. Select positive purchases for this canonical format. Allowed reviewed types: expense, refund, payment, transfer, income, unknown. A blank category is suggested or left Uncategorized. Do not assume an unfamiliar bank's amount sign.

For Excel exports, save the transaction worksheet as UTF-8 CSV in a local spreadsheet application. Keep date years, decimal amounts and currencies intact. Remove summaries only after reconciling them; preserve the original workbook. Opening/exporting in a cloud spreadsheet may upload private activity, so use a local application for the local-only workflow.

PDFs can be dropped directly into Spending as local references. Uploading does not parse them or start analysis. Automatic PDF-to-transaction ingestion is not implemented; requested agent analysis uses available extraction tools and reconciles the evidence. The plugin bundles scripts/extract_pdf.py to produce a private text file locally with an already-installed pdftotext executable. It does not identify transactions or perform OCR. Run it with the source PDF and a new destination text path. It refuses overwrites and prints only a row-free completion message. If pdftotext is unavailable, use an installed local PDF application to copy/export text; do not upload the statement to an online converter. Scans, password-protected or unusual PDFs require local OCR/unlocking and manual review; don't pass passwords in command-line arguments.

Normalize the extracted activity into the canonical CSV locally. Reconstruct wrapped merchant names, dates and page boundaries. Infer a missing year only from the statement period and verify December/January transitions. Classify payments, cash advances, fees, interest, rewards credits and refunds by section and source label. Reconcile transaction count and debit/credit section totals before import. Never include opening/closing balance, minimum due, available credit, APR, running balances or page totals as activity. If reconciliation fails, keep the file unimported and report the discrepancy.

Do not read the extracted statement into model context without the user's informed request for assisted analysis. Direct browser CSV processing requires no model call; agent-assisted PDF interpretation can send content to the host/model provider. This difference must remain visible.

Limitations: comma-separated UTF-8 CSV; ISO/US dates with years; amounts up to two decimals; 1.2 MB per source and 10,000 stored rows. No currency conversion, automatic account sync, investment lot accounting, tax classification, XLSX workbook export or general PDF/OCR transaction parser. Export before clearing a full ledger. Source files and exported copies stay on disk after deleting spending.json in the dashboard.
